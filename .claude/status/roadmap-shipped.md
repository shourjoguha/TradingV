## Retrospective notes (1 line per phase)

- **Structured chart references + channel vignette auto-enrichment** (2026-05-14): operator wanted L3 captions converted into **structured, retrievable signal** so the inference layer can answer queries like "what 4H BTC candle references happened in past 90 days" without LLM-parsing prose at retrieval time. Three-stage extraction chain in `tools/vault_indexer/ingest/`: **Stage 1** `vlm_adapter.caption_frame_structured` runs Qwen2-VL with a YAML/JSON prompt for `chart_type` + `timeframe` + `tickers` + `topics` + `caption`. **Stage 2** `chart_extractor.extract_from_caption` regex-salvages chart-type + timeframe + tickers from the prose when Stage 1 emits empty signal. **Stage 3** `vlm_adapter._regex_salvage` is field-by-field last-resort extraction from raw output when YAML/JSON parse fails (Qwen2-VL frequently emits JSON-fenced-as-YAML with hallucinated repeats; field-by-field salvage recovers ~100% of frames). Ticker whitelist: dynamic union of `roster ∪ all boards ∪ The Street tier-1/2 last 4 snapshots`, loaded at start of each ingest tick. Static stoplist (`AI`, `USA`, `GDP`, etc.) filters acronym noise even with empty whitelist. **Channel `_index.md` auto-enrichment** via `vignette_updater.py`: sentinel-bounded auto-section (`<!-- AUTO:chart-references:start --> ... <!-- AUTO:chart-references:end -->`) keeps a rolling table of recent chart references per channel, FIFO-evicted at `rollup_cap` (default 10), dedupe-keyed on `rel_path` (the markdown link target). Operator-authored content above and below the markers is preserved on every upsert. **Video-level summary block** inserted above the Visual Notes table by `render_draft` when chart_references present: `**Charts referenced (5):** 2× line, 1× bar; **Timeframes:** 4h, 1d; **Tickers:** AAPL, MSFT, AMZN; **Topics:** ...`. **Per-channel toggle** `vision.chart_extraction.enabled` default `false` — fitness/nutrition channels pay zero cost. **fx-evolution-daily + click-capital opted in**. Stage 1 ticker hits NOT in whitelist captured on `VisionResult.unknown_tickers` (currently logged-only; wired to ticker-review queue in next-session Commit 2). **Pilot results** (click-capital, frame_budget=5, both toggles on): 5/5 frames produced structured `chart_references` with chart_type + timeframe + ticker triples; captions clean (no raw YAML leakage in the rendered table). New tests: 13 chart_extractor + 14 vignette_updater + 6 new video_vision (chart_extraction wiring) = 33 net new. Full suite **668 pass** (was 612). Plan: `.claude/plans/ok-now-we-have-distributed-anchor.md` "Structured chart references" + "Phase D" sections (D deferred to Commit 2). Sharp edges: (1) Qwen2-VL structured output stability is shakier than free-form — regex salvage is mandatory, not optional; (2) `app.watchlist.service.list_symbols` + `app.boards.service.list_boards` require the FastAPI `Settings` env (DATABASE_URL + API_KEY) — when CLI runs the whitelist loader without these, watchlist/boards silently degrade to empty and The Street alone fills the universe (~29 entries observed); not a regression for the channel poller which runs under the FastAPI lifespan.
- **MLX acceleration — Whisper adapter + L3 semantic captions** (2026-05-14): operator's L2 pilot answered "captures source attributions + on-screen text" but couldn't answer "what chart TYPE" or "what TIMEFRAME on the candle chart" because Tesseract OCR only reads text. Operator approved L3 (local VLM) but only via MLX (Apple Silicon GPU) — CPU was too slow (~2-3s/frame). Same MLX rationale extended to existing Whisper transcription (audio path was openai-whisper on torch CPU, ~3-5× slower than MLX-Whisper on M3). Adapter pattern keeps tests + non-Apple-Silicon environments working. **Phase 1 — Whisper adapter** (`tools/vault_indexer/ingest/whisper_adapter.py`): `_mlx_available()` checks Darwin+arm64+importable `mlx_whisper`; `FORCE_TORCH_WHISPER=1` env override; `transcribe()` and `transcribe_with_segments()` route to MLX or torch; failure returns `""` (never raises). Both call sites (`ingest_video.py:transcribe`, `youtube_channel.py:whisper_transcribe`) updated to use the adapter — signatures unchanged so existing test mocks at line 444 still hit. **Phase 2 — VLM adapter** (`tools/vault_indexer/ingest/vlm_adapter.py`): module-level singleton model cache (loaded once per process, ~10-15s warm-up); `caption_frame()` calls `mlx_vlm.generate` for a single frame; boilerplate stripper (`"The video frame shows X" → "X"`); `DISABLE_MLX_VLM=1` env override. Originally pinned `Moondream2` but `mlx-vlm 0.5.x` doesn't include moondream2 weights — pivoted to `mlx-community/Qwen2-VL-2B-Instruct-4bit` (~1GB disk, 2B params, 4-bit quantised). CLI gained `--semantic-captions` flag for pilot. **Sharp edge:** thread-based per-frame timeout removed — MLX maintains a thread-local GPU stream so `ThreadPoolExecutor`-based timeouts fail with "There is no Stream(gpu, 1) in current thread" on second-and-later calls. Frame-budget cap at the orchestrator is the real cost bound. **Tests:** 12 new whisper-adapter tests + 11 new vlm-adapter tests + 8 new video_vision tests (3-column path, L3 enable/disable, fallback when VLM unavailable). Full suite **612 pass** (was 573 + 31 new). **Pilot:** ran against `https://www.youtube.com/watch?v=TWeitsa7f4s` (click-capital) with budget=6, semantic_captions=on → 6/6 frames captioned in ~30s wall (including video DL + scene detect + OCR + caption). All other channels untouched (default false). **Disk added:** ~1GB (Qwen2-VL-2B-4bit). New deps: `mlx-whisper`, `mlx-vlm`. ## North-star principles

1. **Trust before action.** Every "tradeable" claim must be backed by visible accuracy data sliced by `(ticker, horizon, model)`. Aggregate stats lie.
2. **Cheap reversibility.** Every phase tagged in git; rollback path documented in `backups/ROLLBACK.md`.
3. **Single-user, opinionated UX.** No auth tiers, no permissions. The cost of premature generality is higher than the cost of refactoring later.
4. **External channels stay external.** This app is the *quantitative pillar*; news, policy, expert commentary, manual TV chart reads stay out of scope. Plug in only data the model itself emits or that's required to evaluate it.

## Locked decisions (2026-04-27)

| Decision | Choice |
|---|---|
| Accuracy metrics | MAPE, RMSE, directional hit-rate (all three, computed per `(ticker, horizon, model)`) |
| Backfill scope | Existing prediction history only — no special historical batch job |
| Drift threshold | Recent-30d MAPE > 1.5× all-time MAPE for that pair triggers flag (start strict, tune after 1 week of data) |
| Notification channel | Telegram bot (single channel for v1; email deferred) |
| Sequencing | Snapshot → Trust → UX → Actionability → Push → Journal → Options runway |

## Phase 1 — Trust through feedback · ~1.5 weeks · PRIORITY

**One mandate**: prove or disprove Kronos accuracy at every `(ticker, horizon, model)` pair you might trade.

### 1.1 — Accuracy backfill + persistence (~3 days)

New table `prediction_accuracy`:
```sql
prediction_accuracy(
  id, prediction_id FK, ticker, horizon_bars, model_id,
  predicted_close NUMERIC, actual_close NUMERIC,
  error_pct NUMERIC,           -- (actual - predicted) / actual
  error_abs NUMERIC,           -- |actual - predicted|
  direction_correct BOOL,      -- sign(predicted_change) == sign(actual_change)
  generated_at TIMESTAMPTZ,
  evaluated_at TIMESTAMPTZ,
  UNIQUE(prediction_id)        -- idempotency
)
```

Background job `accuracy_evaluator()` ticks daily after market close: pulls all `prediction_points` whose horizon has elapsed and aren't yet in `prediction_accuracy`, fetches `actual_close` via existing OHLCV provider, computes errors, inserts row. Idempotent.

Backfill: run once on existing `prediction_points` history (~5 jobs of data). No special historical batch.

### 1.2 — Per-(ticker, horizon) accuracy dashboard (~3 days)

New page `/accuracy`:
- **Heatmap table**: rows = watchlist tickers, columns = horizons in scheduled run (1d, 3d, 5d, 10d). Cells = directional hit-rate over last 30 evaluated predictions (color-graded: green ≥ 60%, yellow 50-60%, red < 50%). Secondary metric (MAPE %) shown on cell hover.
- **Drilldown** on cell click: scatter plot predicted vs actual (diagonal = perfect), MAPE/RMSE/hit-rate trio, sparkline of accuracy over time, list of recent prediction ↔ actual pairs.
- **Filters**: date range, model_id (when ensemble lands).

### 1.3 — Drift detection + Telegram alerts (~3 days)

Daily cron compares last-30d MAPE to all-time MAPE per `(ticker, horizon, model)`. Flag if recent > 1.5× all-time AND ≥ 10 evaluations in recent window (avoid noise on sparse data).

New table `drift_alerts(id, ticker, horizon, model_id, recent_mape, allTime_mape, ratio, flagged_at, acknowledged_at)`.

Telegram integration:
- Bot setup via @BotFather (one-time, manual).
- New env var `TELEGRAM_BOT_TOKEN` + `TELEGRAM_CHAT_ID` (your DM with the bot).
- New `app/notifications/telegram.py` posts markdown messages.
- Drift alerts → Telegram immediately. Daily morning digest (Phase 4) reuses same channel.

Drift alerts also surface as a banner on `/accuracy` and `/` (dashboard) until acknowledged.

### Phase 1 exit criteria (gates Phase 3)

- ≥ 1 `(ticker, horizon)` pair with directional hit-rate ≥ 60% over ≥ 20 evaluations.
- Accuracy dashboard renders without empty states for all watchlist tickers.
- Telegram drift alert verified end-to-end (force a drift via test data).

If exit fails → pivot to retraining / model-side investigation, not Phase 3.

## Phase 3 — Actionability bridge (signals layer) · ~2 weeks

**Predicate**: Phase 1 exit criteria met.

### 3.1 — Opportunities table + signal generator

```sql
opportunities(
  id, ticker, kind ENUM('buy','sell'), generated_at,
  source_prediction_id FK, source_model_id,
  rule_id, rule_label,
  predicted_move_pct NUMERIC, confidence NUMERIC,
  status ENUM('open','acted','expired','dismissed'),
  expires_at,
  acted_at, dismissed_at, dismissed_reason
)
```

Hardcoded rules to start (NOT a DSL):
- `R1`: predicted_move_pct ≥ +2% over 5d AND historical_hit_rate ≥ 0.60 → BUY.
- `R2`: predicted_move_pct ≤ -2% over 5d AND historical_hit_rate ≥ 0.60 → SELL.
- `R3`: predicted_move_pct ≥ +5% over 10d AND historical_hit_rate ≥ 0.55 → BUY.
- (Tune after 2 weeks of real signal data.)

Generator runs after each scheduled prediction batch.

### 3.2 — Opportunities UI

New page `/opportunities`:
- Today's open list (sorted by confidence × predicted_move).
- History tab (acted + dismissed + expired with realized outcomes).
- Per-row actions: mark acted, dismiss (with reason).
